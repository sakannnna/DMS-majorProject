# MongoDB 问卷系统第一阶段报告

2026-10-16。第一阶段已按确认范围实现并验证，代码与材料基线为 Git 标签 `stage1-v1`。本报告供教师评估完成情况；当前需求和设计只在[需求与设计](需求与设计.md)维护，测试事实只在[测试记录](测试记录.md)维护。

## 项目目标和完成范围

系统提供简化在线问卷能力：注册登录后创建和管理自己的问卷，配置单选、多选、文本与数字填空，设置校验和条件跳转；通过链接让其他登录用户填写；明确确认后保存答卷，创建者查看整卷和单题统计。界面采用普通表单，重点放在数据库组织、后端规则、权限与可验证行为。

采用 Python 3.12、FastAPI、PyMongo 和 MongoDB，Jinja2 与原生 JavaScript 提供同源页面。用户确认技术栈、四集合及关键业务规则；代码、文档编写和本次实际测试均由 Codex 完成。没有将 AI 工作记为用户手工实现。

## 系统与 MongoDB 设计

系统保持单应用结构：请求模型、认证模块、校验与跳转模块、数据库初始化及接口模块各有职责，页面与 API 使用同一套后端业务检查。入口、运行和环境配置见 [README](../README.md)，接口使用及自动生成契约见 [API说明](API说明.md)。

四集合为 users、surveys、responses、sessions。题目、选项、校验和跳转规则嵌入问卷，答案嵌入每份独立答卷，账号和跨主体关系使用引用。这样常用的完整问卷可一起读取和验证，持续增长的答卷不塞入问卷大数组。数据库通过 validator 检查基本结构，通过唯一及部分唯一索引保证账号、链接、重试和单次填写约束；统计直接聚合答卷，不额外维护容易失配的计数。

该设计基于问卷访问与更新方式组织文档，并非认为关系数据库不能完成问卷系统。作业指定 MongoDB，异构题型与嵌套配置适合在文档聚合中表达。完整理由、关系图、索引和版本字段以当前设计及 [database.py](../app/database.py) 为准。

## 跳转校验和权限

单选、多选及数字题均可配置规则；按顺序首条命中，只向后或结束，无命中进入下一题。结束与自然答完均进入提交确认，不自动保存。提交时从第一题重放路径，验证到达题目的回答，拒绝未知、重复和路径外答案；被跳过的必答题不要求作答。多选数量、文本长度、数字范围与整数要求在服务端执行，数值0和未答分开处理。

创建者只能管理和统计自己的问卷；所有填写者均需登录。匿名仅向创建者隐藏账号，内部保留用户关联做次数限制。发布后冻结题目、选项、校验、跳转及匿名和重复设置；允许改标题、说明和截止时间，已关闭不能重开。以上具体解释是用户确认的本项目设计规则，不冒充教师原文明示要求。

## 测试结果和实际问题

47 项自动测试全部通过，覆盖六类必测及权限、数据库结构、重试、并发、发布后编辑、截止关闭和重启保留数据。通过真实 MongoDB 测试库检验唯一约束与聚合，没有仅以模拟对象证明数据库行为。浏览器验证通过账号、含规则问卷编辑、预览、发布冻结、发布后说明修改、数字越界、提交确认及统计；截图和步骤见测试记录。

实际发现并修正两项 AI 实现错误：认证依赖缺少 Request 标注，导致首轮8项接口测试失败；前端规则读取选择器过宽，导致含规则草稿保存失败。前者补上类型标注后自动测试通过，后者收紧容器选择器后重新走页面验证通过。代码检查还修正了无效跳转目标或选项应保留显式错误、不能静默替换的问题。未虚构用户排错或手工修改经历。

仍有一条第三方测试客户端弃用警告，不影响当前47项测试；没有为消除警告再安装组件。尚未执行压力、长期运行、跨浏览器全面测试或公网部署。关闭采用提交前最后一次状态检查作为准入，已准入的在途写入可能在关闭后完成；这不是跨集合严格瞬间阻断保证。统计在有新提交时可能随查询变化，未实现跨多个统计请求的快照。
